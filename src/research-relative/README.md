# Public-data relative acoustic classifier

This is an isolated browser port of the frozen three-class relative SVM. Its API is:

```ts
predictRelative(samples: Float32Array, sampleRate: number, times: number[], signal?: AbortSignal): Promise<Array<'hat' | 'kick' | 'snare'>>
```

Pass **all predicted hits from the recording**, including those that may be false detections. Recording-level normalization depends on this complete set. The API preserves samples/timestamps, resamples through OfflineAudioContext to 16 kHz, and executes features/SVM inference in a disposable worker. Aborting terminates that worker. It never uploads audio.

**Do not use this model unconditionally.** It was trained on mixed-instrument grooves and subtracts recording medians. A predefined six-file isolated-sound diagnostic on validation performers 15/20 produced only 84/200 correct labels, even with reference boundaries. A single event normalizes to an all-zero vector. A separately justified diversity gate/fallback is necessary for application integration. This module provides no gate itself.

## Model provenance and attribution

Training audio: **Alejandro Delgado Luezas, Amateur Vocal Percussion Dataset v3**, [Zenodo 3250230](https://zenodo.org/records/3250230), **CC BY 4.0**. The frozen model uses public performers 1–14 annotated grooves only. No private user audio, private profile weights, or evaluation labels enter this binary.

`model.json` records dimensions, numerical section formats, source/license, and SHA256. The binary is **3,177,704 bytes**, compared with the previous 15,547,790-byte JSON. Support vectors are stored losslessly as Float32—they were originally Float32 input values promoted by sklearn. Scaler parameters, dual coefficients, and intercepts retain Float64. No quantized approximation was substituted.

The feature algorithm follows the existing Python pipeline: 500 ms event crop with 10 ms attack context, mean removal/peak 0.8 normalization, Kaldi 128-band log-power filterbanks with 25 ms Povey windows, 10 ms hop, frame DC removal, 0.97 preemphasis and no dither. It includes the original Float16 bank round-trip, multiframe means/stds/DCT, complete-recording median/std normalization, sklearn scaling, and LIBSVM one-vs-one votes. Equal vote totals retain the earliest class. Scores are not calibrated confidence probabilities.

The exported coefficients are generated by `ml/export_relative_binary.py` using the installed torchaudio Kaldi implementation and scipy DCT. Browser FFT evaluation uses the existing fft.js dependency. This is numerical parity testing, not a claim of new recognition accuracy.

## Verified behavior

- **20,397/20,397** cached public events produce identical model labels. Maximum descriptor difference 1.44e-6, normalized feature difference 8.39e-6.
- **777/777** actual-audio events across 14 recordings match Python labels when given the same 16 kHz samples. The real-audio bank differences observed in the initial four recordings were at most 0.0009766, with mean error below 3.5e-7. Floating-point FFT cancellation at near-silent high-frequency bins can produce slightly larger differences in the synthetic pure-tone unit fixture (maximum 0.00390625); its descriptor tolerance is 0.0005.
- **Native browser resampling is not numerically identical to librosa/soxr.** Across 12 validation grooves it changes 28/706 individual labels. With the fixed Python onsets, native resampling gets 591/672 correct matched core labels (87.95%) versus Python 592/672 (88.10%).
- Fully native browser onset detection plus this classifier yields 707 detections, 694 references, 672 matched events and 590 correct core labels: **95.93% onset F1, 87.80% matched classification, 84.23% labeled end-to-end F1**. These are previously inspected validation recordings, not a new blind test.
- A 100-hit worker call took about **198 ms** in headless Chromium on this Mac. This performance probe repeats public audio and is not an accuracy benchmark or a mobile-speed promise.
- Input preservation, already-aborted and in-flight cancellation, empty hit lists, malformed times, and browser console errors were checked. The dedicated four-test numerical suite and TypeScript checking pass.

This model only returns **hat/kick/snare**. It cannot distinguish open/closed hats or establish ride/crash/aux accuracy. Application code must preserve that limitation.

Training and research scripts are maintained on the [research/audio-classification branch](https://github.com/g-h-miles/beatbox/tree/research/audio-classification).

## Reproduce

```sh
python ml/export_relative_binary.py
npx tsx scripts/relative-parity-cached.ts
npx tsx scripts/relative-parity-audio.ts
npm run dev -- --port 5178
node scripts/relative-parity-browser.mjs
npx vitest run tests/relative.test.ts
```

Full public-data numerical, browser, and isolated diagnostic reports are under ignored `artifacts/relative-parity`. The browser harness deliberately has no app/HMR client so ongoing UI edits do not destroy its evaluation context.
